# Benchmark capture qualification

## Status

- **Purpose:** qualify captured EDVR benchmark rows without confusing collection, feature activity and physical display delivery.
- **Inputs:** normalized acquisition records, their schema 2 qualification envelope, exact graphics/OpenXR parser-stream bytes, and a live capture receipt.
- **Scope:** read-only validation and optional creation of a fresh result file. This does not launch the game or change its settings.
- **Limit:** submission counts describe application `xrEndFrame` delivery; they do not establish physical scanout or successful hardware frame generation.

Run `python tools/edvr_benchmark.py --self-test` for the regression fixtures. The same gate runs in `build.bat`.

The controller keeps wire parsing in the acquisition parser. A receipt binds before/after PID, process creation ticks, image and Windows session to an owned capture session, full source commit, configuration SHA-256 and exact raw source hashes and lengths. Acquire those live identities around the capture; copying an old receipt is not a fresh observation. When the sanctioned reader stitches rotated logs, retain its logical UTF-8 byte streams as parser sources and export the original closed on-disk segments separately with their own hashes. These are distinct source populations and their hashes can differ.

At qualification production, call `produce_qualification(run, row, records, receipt, sources, aggregate_records=..., qualify_report=...)`. The trusted adapter supplies `aggregate_records(records, run)`, which returns `(summary, intervals)`, and `qualify_report(report, row)` in code. The producer recomputes the aggregate from copies of verified, already annotated records and passes the resulting schema 1 report to the qualifier. Recomputing must leave the normalized records unchanged. The producer accepts neither a cached aggregate nor a detached reviewed result. Store its returned envelope in `capture.qualification` and pass it with `run`, `row`, `records`, `receipt`, `sources` and `collection_status` to `qualify_capture`.

The envelope has `schema` (integer `2`), `qualification` (the complete reviewed payload) and `binding` (lowercase SHA-256). The digest covers a JSON object with `schema`, complete `run`, `row`, `records`, `receipt`, and `qualification`, plus `sources` keyed by `gfx` and `openxr`, each with verified `sha256` and `bytes`. Serialize as UTF-8 JSON with recursively sorted string keys, compact separators `(',', ':')` and ASCII escapes; retain array order and exact integers, and reject nonfinite numbers. The verifier recomputes this digest from its own verified inputs and refuses bare, unknown-schema or mismatched envelopes. It cannot create a binding for a detached qualification. These are mixed-capture and provenance checks; SHA-256 here does not authenticate the producer or establish that an untrusted parser interpreted the original bytes correctly.

Every embedded FG admission observation must match the line digest, mapped timestamp and fields of a normalized record marked qualified for the settled row. Lifecycle observations require OpenXR provenance; producer source and camera refusals require graphics provenance. The verifier checks both source roles against the supplied bytes. Prior setup records may remain in the capture, including DLSS mode evidence recorded before the settled interval.

For file-based use, put those arguments except `sources` in a capture JSON object and pass `--input capture.json --gfx graphics.log --openxr openxr.log`. Add `--output result.json` to create a new file; an existing output is refused. `--dry-run` prints the qualified result and creates nothing, including when `--output` is supplied.

The row declares `expected_output_dimensions` as left width, left height, right width, right height. Native AA-off requires input and output to match that target. A runtime timing record with unavailable 0×0 input metadata cannot substitute for application dimension proof.

Results keep collection outcome, clean timing-window coverage, requested settings and actual feature qualification separate. A regression in any known cumulative counter invalidates that submission interval, including regressions in empty, failed or background counts. Native, generated, repeated and total rates each carry their own known-counter coverage; missing counters remain unavailable and observed zero stays zero. Total uses intervals where all three reported component counters are known. An active multiplier alone does not prove generated delivery. If generated counts cover only part of the observed intervals, a known zero remains partial unless other evidence establishes a contradiction.

Diagnostics include only benchmark windows contained in the settled row through drain. Boundary-crossing windows remain whole and separate. CPU producer wall time, application GPU time, runtime cycle phases and raw DXGI Present remain separate populations; nested phases are not additive and runtime late frames are not physical dropped frames.

For desktop navigation, `python tools/edvr_screen.py --capture capture.png --profile profile.json --context context.json --expected-state state` returns success only when one calibrated state matches and it is the requested state. The tool reads files and prints a decision; it never sends input. The caller owns capture freshness, process identity, focus, and input safety.

The explicit profile (schema 2, `screen_checks` schema 1) declares the actual source client width and height, allowed output edges, expected neutral HMD matrix, and the states and their templates. Each variant applies only at its exact output edge. Context carries the observed source and PNG dimensions, profile ID, and actual observed pose and simulator serial. PNG dimensions must agree with both the context and the scaled client dimensions, including nearest-pixel rounding. ROIs use a normalized 1024-unit grid on both axes. Every ROI must meet at least 0.90 intersection over union; multiple matching states fail. Validate calibration against independent manually labeled captures before using it to guard input. The screen check does not qualify render timing, per-eye output, or physical scanout.
